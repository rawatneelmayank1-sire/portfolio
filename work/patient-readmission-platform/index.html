Patient Readmission Risk

A leakage-free model predicting which diabetic patients return to hospital within 30 days.

Open the repositorySkip to the problem

Problem

Many readmission demos split by encounter, so the same patient leaks into the test set. Scores then look better than they really are.

What it does

  • Cleans 101,766 hospital encounters into a cohort of 69,990 patients.
  • Splits by patient so nobody appears in both training and test data.
  • Trains logistic regression and gradient boosting, then calibrates both risk scores.
  • Reports metrics with confidence intervals and recall by age, gender and race.
  • Serves the calibrated model through a FastAPI predict endpoint.

Architecture

A Python package with a command-line entry point and make targets for data, train, evaluate and serve. The FastAPI service returns a calibrated risk, a flag, the threshold and the model version.

How it works

  1. Clean

    Map code ids to names, group ICD-9 diagnosis codes, handle missing values, count medications.

  2. Cohort

    Drop death and hospice discharges and keep each patient's first stay: 69,990 patients.

  3. Split

    Group by patient into 70 / 15 / 15 train, validation and test sets, seed 42.

  4. Fit and calibrate

    Train both models with balanced class weights, then isotonic calibration on validation patients.

  5. Threshold

    Pick the lowest validation threshold reaching 20% precision; choose the model by validation PR-AUC.

  6. Evaluate

    Score the untouched test set once with bootstrap 95% intervals and fairness slices.

Results

Design decisions

  • Patient-level split blocks leakage, since about 30% of encounters are repeat patients.
  • Calibration after balanced weights makes a predicted 10% risk mean about 10% readmitted.
  • Threshold set on validation only; the test set is touched once.
