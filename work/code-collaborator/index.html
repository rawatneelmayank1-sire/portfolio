Code Collaborator

A shared browser code editor where concurrent edits merge cleanly and code runs for the whole room.

Open the repositorySkip to the problem

Problem

The first version sent the whole file on every keystroke and the last message won. Edits vanished and cursors jumped.

What it does

  • Lets users join a room by ID or invite link and edit code together live.
  • Merges concurrent edits with the Yjs CRDT and shows each participant's cursor.
  • Saves each room's state so a refresh or server restart keeps the code.
  • Runs JavaScript, Python, Java or C++ and shares the output with the room.

Architecture

One Node.js process with Express and ws serves the run API, the Yjs WebSocket and the built React client. Run results reach every browser the same way edits do, through the shared document.

How it works

  1. Join

    The client opens a Yjs WebSocket; the server checks origin, room name, display name and a 20-person limit.

  2. Load

    The room loads once; concurrent joins share the same load, so memory never holds two copies.

  3. Type

    Monaco edits a shared Y.Text and only the small update travels over the socket.

  4. Merge and broadcast

    The server applies each update to the room document and sends it to every other connection.

  5. Save

    A snapshot is written 750 ms after changes; idle rooms unload 30 s after the last person leaves.

  6. Run

    The server runs the code held in the document and writes the output back into it.

Design decisions

  • Rebuilt syncing on a CRDT so every copy converges, instead of last-write-wins.
  • Code is read from the shared document, not the request, so the room runs what it sees.
  • Pluggable runner: self-hosted Piston sandbox or a local runner, with a plain error if none is reachable.
