URL Shortener

A Spring Boot link shortener whose redirect path never writes to the database.

Open the repositorySkip to the problem

Problem

Redirects must stay fast and must not fail when analytics is slow. Click logs hold IP addresses, so they must stay private to the link owner.

What it does

  • Shortens long URLs into random Base62 codes or validated custom aliases, with optional expiry.
  • Redirects through a Redis cache that never outlives the link.
  • Counts clicks asynchronously through Kafka with a single consumer as the only writer.
  • Rate limits each client with a Redis sliding window run as one Lua script.
  • Shows click stats only to the link owner; everyone else gets 403.

Architecture

One Spring Boot app with PostgreSQL, Redis and Kafka in Docker Compose. Health checks and Prometheus metrics sit on a separate management port.

How it works

  1. Rate limit

    One Lua script on a Redis sorted set allows 100 requests per 60 s, else 429.

  2. Check format

    A code that cannot be valid returns 404 without touching Redis.

  3. Cache read

    Read the link from Redis; a Redis error counts as a miss so redirects keep working.

  4. Cache miss

    Load from PostgreSQL; expired or deactivated returns 410; else cache with TTL capped at expiry.

  5. Publish click

    Send a click event to Kafka, waiting at most 1 s, then return 302.

  6. Count

    The consumer saves the click row and increments the counter with one atomic SQL update.

Design decisions

  • Click counting moved off the redirect, removing a double count from two writers.
  • Client IP read only from trusted proxies, so a spoofed header cannot bypass the limiter.
  • Errors return RFC 9457 problem details with precise status codes, not a blanket 400.
