HaulPulse

A daily batch pipeline that loads messy delivery-trip files and proves it caught every defect.

Open the repositorySkip to the problem

Problem

Delivery trip files arrive dirty and late. KPIs built on them are wrong unless every bad row is caught and explained.

What it does

  • Loads about 5,000 synthetic last-mile trips a day into PostgreSQL bronze, silver and gold layers.
  • Checks every row against 16 validation rules and quarantines rejects with every reason.
  • Builds a dbt star schema with SCD Type 2 driver history and 3 KPI marts.
  • Reconciles quarantine counts against a manifest of injected defects.
  • Shows city demand, drivers and pipeline health in a Streamlit dashboard.

Architecture

One PostgreSQL database with five schemas: Python handles bronze and silver, dbt builds gold, Streamlit reads analytics and Airflow schedules everything. Every task writes load logs, run rows and alerts to an ops schema.

How it works

  1. Generate

    A seeded generator writes daily trips, makes 7% dirty in 12 ways and records a defect manifest.

  2. Load bronze

    Header check, PostgreSQL COPY into text columns, replace that file's rows, verify row counts.

  3. Validate silver

    Fix spellings, apply the rules, quarantine bad rows, upsert clean rows where newest updated_at wins.

  4. Build gold

    dbt snapshots drivers, builds dimensions, an incremental fact watermarked on loaded_at, and KPI marts.

  5. Test and reconcile

    50 dbt tests run, then reconcile matches every injected defect type to quarantine counts.

  6. Orchestrate

    A 10-task Airflow DAG runs daily with 2 retries and writes failures to an alerts table.

Design decisions

  • Watermark on load time, not trip time, so backfilled late corrections are never skipped.
  • Every step is idempotent, so re-running a file or a day never duplicates data.
  • Indexes measured on 1M rows; partitioning was measured and deferred to about 10x volume.
